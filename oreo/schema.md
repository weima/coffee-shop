# Oreo SQLite Schema

## Reason for existence

Define the durable v1 tables, constraints, and metadata indexes before the session store is implemented. The store owns this schema and all SQL; `oreo/src/sqlite` owns only the Odin-to-SQLite binding.

## Version and conventions

- Schema version: `1`, stored in SQLite's `PRAGMA user_version`.
- Engine: official SQLite `3.54.0`, amalgamation archive [`sqlite-amalgamation-3540000.zip`](https://www.sqlite.org/2026/sqlite-amalgamation-3540000.zip), SHA3-256 `7b670a62fdfbd672b75fef004cb703c8a3e87d3a5cc7d675b4a08337004a2d93`.
- Tables use SQLite `STRICT` typing. IDs are opaque, stable text identifiers generated by Oreo; the schema does not depend on their encoding.
- Timestamps are UTC Unix epoch milliseconds in `INTEGER` columns. They are application timestamps, not SQLite's implicit `CURRENT_TIMESTAMP` text values.
- Enable `PRAGMA foreign_keys = ON` on every connection. Create a new schema and set `user_version = 1` in one transaction. Refuse a database with a newer unsupported schema version.
- The database is `~/.oreo/sessions.db`. Keep the containing directory and database private to the user. Closing a session or expiring queued work never deletes history.

## DDL

The executable v1 schema is [`src/store/schema.sql`](src/store/schema.sql). Oreo's store embeds and applies this file; keep it as the single source of truth for table and index definitions. The store enables foreign keys before initialization and sets `user_version` in the same schema transaction.

## Contract

### Sessions

A session is one top-level task. V1 metadata lookup fields are `session_id`, `title`, `status`, `created_at_ms`, and `updated_at_ms`; V1 does not add arbitrary key/value metadata or full-text search. `closing` prevents new submissions while queued and active work is cancelled. Set `closed_at_ms` only when the session reaches `closed`. Close preserves all rows.

### Provider profiles and work items

A provider profile is the immutable tuple `(provider, model, thinking)`. The caller supplies all three settings for each work item; Oreo may deduplicate identical tuples into one profile row, but dispatch always resolves the work item's explicit `profile_id`. A profile does not contain account selection, access tokens, or credentials.

`request` stores the exact initial work-item input. A work item can pause as `needs_input` and resume through the queue. `expires_at_ms` is an optional queue deadline and applies only before the first dispatch (`started_at_ms IS NULL`); it is not a run timeout and does not expire paused or running work. Expiry changes status to `expired` and retains the request and records. On host restart, do not replay work: mark every unfinished work item `interrupted`, except a never-started queued item whose deadline has already passed, which becomes `expired`.

Terminal work-item states are `completed`, `failed`, `cancelled`, `interrupted`, and `expired`. Active cancellation is cooperative: set `cancel_requested_at_ms`, keep the active state until the worker acknowledges stop, then set `cancelled` and `finished_at_ms`.

### Ordered records and indexes

`work_item_records` holds ordered conversation/tool context. `sequence_no` starts at 1 and increases within one work item. `payload_json` is a UTF-8 JSON object owned by the record kind; validate it in Oreo before insertion. SQL does not query JSON fields. The primary key supports ordered replay, so no duplicate sequence index is needed.

The indexes support these v1 lookups:

- Sessions by status/recent update time or exact title.
- Work items by session and submission time.
- The shared scheduler's queued FIFO and expiry scans.
- A work item's complete ordered record stream through the composite primary key.

Use bound parameters for all values. Persist each work-item status transition and any corresponding `work_item_records` row in one SQLite transaction; update the parent session's status and `updated_at_ms` in that transaction as well. Use `PRAGMA user_version` for schema migration state; do not delete history as a migration shortcut. The binding does not own or hard-code these tables.
